# РУКОВОДСТВО ПО ИСПОЛЬЗОВАНИЮ UV ДЛЯ PYTHON

UV - это современная альтернатива pip и pip-tools, разработанная Astral (создателями Ruff). Он предлагает значительное ускорение операций с пакетами Python.

Ссылка: https://astral-sh.vercel.app/blog/uv-unified-python-packaging
Исходный код: https://github.com/astral-sh/uv

---

## ЧТО ТАКОЕ UV

UV - это быстрый Python пакетный менеджер и инструмент для работы с виртуальными окружениями от создателей Ruff. Он заменяет:

- pip
- venv
- virtualenv
- pipenv
- poetry (частично)

## ИМЕНОВАНИЕ ВИРТУАЛЬНЫХ ОКРУЖЕНИЙ

### Стандартные названия

В Python сообществе сложились определенные соглашения по именованию виртуальных окружений:

| Имя | Когда использовать |
|-----|-------------------|
| `.venv` | **Самый популярный** - скрытая папка в корне проекта. Используется по умолчанию в UV, Poetry, и многих IDE |
| `venv` | Классический вариант, без точки. Тоже часто используется |
| `.env` | Обычно используется для переменных окружения, **не рекомендуется** для venv (путаница) |
| `env` | Устаревший вариант, редко используется сейчас |

### Почему .venv лучше

```bash
# .venv - скрытая папка (начинается с точки)
.venv/
├── bin/
├── lib/
└── pyvenv.cfg

# Преимущества:
# 1. Не захламляет ls (не видна без -a)
# 2. Автоматически игнорируется Git (можно добавить в .gitignore)
# 3. Стандарт де-факто для современных инструментов
# 4. IDE (VSCode, PyCharm) автоматически находят .venv
```

### Именование для разных версий Python

```bash
# Если в проекте несколько версий Python
.venv-3.10/
.venv-3.11/
.venv-3.12/

# Или с указанием назначения
.venv-dev/      # Для разработки
.venv-test/     # Для тестирования
.venv-prod/     # Для продакшена
```

### Что добавить в .gitignore

```bash
# .gitignore
.venv/
venv/
env/
*.pyc
__pycache__/
```

## СОЗДАНИЕ ВИРТУАЛЬНОГО ОКРУЖЕНИЯ БЕЗ UV (СТАНДАРТНЫЙ VENV)

Иногда UV не установлен или вы хотите использовать встроенный в Python модуль venv.

### Команда

```bash
# Создать окружение с Python 3.11
python3.11 -m venv .venv

# Создать с Python 3.10
python3.10 -m venv .venv

# Создать с системным Python 3
python3 -m venv .venv
```

### Разбор команды

```bash
python3.11 -m venv .venv
# ^^^^^^^^    ^^ ^^^^ ^^^^^
# Версия      |   |    Имя папки
# Python      |   Модуль venv
#             Запуск модуля
```

### Когда использовать стандартный venv

1. **UV не установлен** - на серверах или в CI/CD
2. **Проблемы с UV** - если UV вызывает ошибки
3. **Обучение** - понять как работает venv "под капотом"
4. **Минимализм** - не хотите устанавливать дополнительные инструменты

### Сравнение: UV vs стандартный venv

```bash
# Стандартный venv (медленно, но надежно)
python3.11 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# UV (быстро, современно)
uv venv .venv --python 3.11
source .venv/bin/activate
uv pip install -r requirements.txt
```

## РАБОТА В ВИРТУАЛЬНОМ ОКРУЖЕНИИ (VENV)

Этот раздел описывает стандартную работу с venv, которую UV использует под капотом.

### Вход в виртуальное окружение (активация)

```bash
# Linux / macOS
source .venv/bin/activate

# Windows (CMD)
.venv\Scripts\activate.bat

# Windows (PowerShell)
.venv\Scripts\Activate.ps1

# Если окружение называется по-другому
source my_venv/bin/activate
```

После активации в начале строки появится название окружения в скобках:

```bash
(.venv) user@host:~/project$
```

### Выход из виртуального окружения (деактивация)

```bash
deactivate
```

После деактивации исчезнет префикс (.venv) из приглашения командной строки.

### Удаление виртуального окружения

```bash
# Просто удалить папку (предварительно выйдя из окружения)
rm -rf .venv

# Или если другое имя
rm -rf my_venv
rm -rf .venv-3.11
```

### Проверка, что вы внутри окружения

```bash
# Посмотреть путь к Python
which python
# Должен показывать .venv/bin/python

# Посмотреть путь к pip
which pip
# Должен показывать .venv/bin/pip

# Посмотреть список пакетов
pip list

# Проверить версию Python
python --version
```

## ДЕТАЛЬНОЕ ИСПОЛЬЗОВАНИЕ ОСНОВНЫХ ФУНКЦИЙ

### 1. Работа с виртуальными окружениями

#### Установка пакетов

```bash
# Глобально (через pipx уже установили)
uv --version

# В проект (создаст venv автоматически)
uv pip install pyinstaller
uv pip install requests pandas

# Установить из requirements.txt
uv pip install -r requirements.txt
```

#### Дополнительные параметры

```bash
uv venv --python=3.10 .venv  # Спецификация версии Python
uv venv --seed .venv  # С предустановкой pip и setuptools
```

### 2. Управление пакетами

#### Установка пакетов

```bash
uv pip install package  # Один пакет
uv pip install package1 package2  # Несколько пакетов
uv pip install -e .  # Установка в режиме разработки
```

#### Установка из requirements.txt

```bash
uv pip install -r requirements.txt
```

#### Особые варианты установки

```bash
uv pip install "package>=1.0,<2.0"  # Спецификация версий
uv pip install --no-deps package  # Без зависимостей
uv pip install --index-url https://pypi.org/simple/ package
```

### 3. Компиляция требований (аналог pip-compile)

#### Базовое использование

```bash
uv pip compile requirements.in -o requirements.txt
```

#### Расширенные опции

```bash
uv pip compile pyproject.toml -o requirements.txt  # Из pyproject.toml
uv pip compile --upgrade package requirements.in  # Обновить конкретный пакет
uv pip compile --all-extras requirements.in  # Со всеми extras
```

#### Генерация разных файлов

```bash
uv pip compile requirements.in -o requirements.txt --python-version 3.8
uv pip compile dev-requirements.in -o dev-requirements.txt
```

### 4. Синхронизация окружения

```bash
uv pip sync requirements.txt  # Точное соответствие requirements.txt
uv pip sync requirements.txt --reinstall  # Принудительная переустановка
```

### 5. UVX - запуск без установки

```bash
# Запустить pyinstaller без установки
uvx pyinstaller --onefile app.py

# Запустить любую Python утилиту
uvx black myfile.py  # Форматировщик кода
uvx pytest tests/    # Запуск тестов

# С конкретной версией
uvx "pyinstaller==5.13" --onefile app.py
```

```bash
# Пересоберем с добавлением hidden import

  --hidden-import "aiohttp" \
  --hidden-import "sqlalchemy" \
  --add-data "config.py:." \
  --add-data "models.py:." \
  --add-data "database.py:." \

# Посмотрим что импортирует database.py

# Выйти из окружения

```

<details>
<summary>ЗАЧЕМ НУЖНЫ --HIDDEN-IMPORT</summary>

Зачем нужны --hidden-import если пакеты уже установлены?

Проблема: PyInstaller анализирует только явные импорты в коде. Но некоторые пакеты используют:
- Динамические импорты - importlib.import_module(), __import__()
- Плагины/расширения - загружаются во время выполнения
- Conditional imports - импорты внутри функций/условий
- Вендорные копии - пакеты внутри других пакетов

```python
# В database.py импортируется create_async_engine
# SQLAlchemy динамически загружает драйвер aiosqlite во время выполнения
# PyInstaller не видит эту зависимость при статическом анализе

engine = create_async_engine(DATABASE_URL, echo=True)
# SQLAlchemy динамически импортирует aiosqlite здесь
```

КАКИЕ --HIDDEN-IMPORT НУЖНЫ ВАМ:

1. aiosqlite - КРИТИЧЕСКИ ВАЖЕН

```python
# database.py использует SQLAlchemy с aiosqlite
# SQLAlchemy загружает его динамически
DATABASE_URL = "sqlite+aiosqlite:///./app.db"
# Без --hidden-import "aiosqlite" получите ошибку:
# ModuleNotFoundError: No module named 'aiosqlite'
```

2. _cffi_backend - для bcrypt

```python
# auth_utils.py использует bcrypt для хэширования паролей
# bcrypt использует CFFI (C Foreign Function Interface)
# _cffi_backend - это нативный модуль
hashed_password = bcrypt.hashpw(password.encode(), bcrypt.gensalt())
```

3. aiohttp - уже виден (можно не добавлять)

```python
# app.py явно импортирует aiohttp
from aiohttp import web, web_request
# PyInstaller видит этот импорт
```

4. sqlalchemy - уже виден (можно не добавлять)

```python
# app.py явно импортирует sqlalchemy
from sqlalchemy import select, or_, desc, text, update, delete
```

ПОЧЕМУ?

- aiohttp и sqlalchemy уже видны (явные импорты)
- _cffi_backend может быть опциональным (предупреждение, но не ошибка)
- aiosqlite - обязателен (динамическая загрузка через SQLAlchemy)

ПРОВЕРИМ ЧТО ДЕЙСТВИТЕЛЬНО НУЖНО:

```bash
# Соберем без hidden imports для теста
pyinstaller --onefile --clean --name test-no-hidden app.py

# Запустим
./dist/test-no-hidden 2>&1 | head -20

# Увидим ошибку про aiosqlite
```

КАК УЗНАТЬ КАКИЕ HIDDEN IMPORTS НУЖНЫ:

1. Соберите без hidden imports
2. Запустите и посмотрите ошибки
3. Добавьте только те модули, которых не хватает

```bash
# Диагностика
./dist/sbc-app 2>&1 | grep -i "ModuleNotFoundError\|ImportError"
```


---

**Рекомендую использовать uvx для разовых задач** (сборка, тестирование), а **uv venv + uv pip** для разработки проектов.
