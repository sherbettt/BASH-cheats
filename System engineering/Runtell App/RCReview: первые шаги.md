## Подготовка окружения

### Шаг 1. Переход в директорию проекта

```bash
cd /opt/runtel/rcreview
```

**Пояснение:**  
Это рабочая директория приложения `rcreview`. Все дальнейшие команды выполняются отсюда.

---

### Шаг 2. Активация виртуального окружения

```bash
source .venv/bin/activate
```

**Пояснение:**  
В Python принято изолировать зависимости проекта от системных. `.venv` — это виртуальное окружение, созданное специально для этого проекта.

**Что делает `source`:**  
Активирует виртуальное окружение, чтобы все команды и пакеты использовались именно из этой папки, а не из глобальной системы.

**Признак успеха:**  
В начале командной строки появится `(.venv)`:
```
(.venv) root@RCR /opt/runtel/rcreview (0)
```

---

### Шаг 3. Установка проекта в режиме разработки

```bash
pip install -e '.[dev]'
```

**Что означают флаги:**

| Флаг | Значение |
|------|----------|
| `-e` (editable) | Код не копируется в системные папки, а используется напрямую из текущей директории. Это удобно для разработки — изменения в коде сразу видны без переустановки. |
| `.[dev]` | Устанавливает сам проект + все зависимости для разработки: тесты, линтеры, средства отладки и т.д. |

---

### Шаг 4. Настройка переменных окружения

```bash
cp .env.example .env
```

**Зачем это нужно:**  
В файле `.env` хранятся важные настройки приложения:
- Параметры подключения к базе данных
- Секретные ключи и пароли
- Порты и режим работы
- Настройки логирования

**Что мы делаем:**  
Копируем файл-пример `.env.example` в рабочий файл `.env`.  
*(он уже отредактирован под свои нужды, указав правильные параметры БД и другие настройки)*

---

### Шаг 5. Применение миграций базы данных

```bash
rcreview-migrate upgrade head
```

**Что такое миграции:**  
Это специальные скрипты, которые создают или изменяют структуру базы данных. Каждая миграция — это версия схемы БД.

**Что делает команда:**
- `upgrade` — применить миграции
- `head` — применить все последние изменения до самой свежей версии

**Почему это важно:**  
Без миграций база данных будет пустой или иметь неактуальную структуру, и приложение не сможет работать с данными.

## Запуск приложения

### Шаг 6. Запуск API-сервера

```bash
rcreview-api
```

**Что это такое:**  
Это FastAPI-приложение, которое обслуживает:
- Веб-интерфейс (сайт)
- API (программный интерфейс для взаимодействия)

**Характеристики:**
- Слушает порт: **8080**
- Доступен по адресу: `http://0.0.0.0:8080` (все интерфейсы)
- После запуска видно:
```
Uvicorn running on http://0.0.0.0:8080 (Press CTRL+C to quit)
```

**Важно:**  
Сервер должен работать постоянно. Для остановки нажмите `Ctrl+C`.

---

### Шаг 7. Запуск воркера (опционально, в другом терминале)

```bash
rcreview-worker
```

**Что такое воркер:**  
Это фоновый процесс, который обрабатывает длительные задачи:
- Анализ кода
- Отправка уведомлений
- Периодические задачи
- Обработка очередей

**Примечание:**  
В нашем случае мы запустили его, но остановили через `Ctrl+C` для упрощения. Для полноценной работы приложения он должен быть запущен.

## Доступ к сервису

### Шаг 8. Определение IP-адреса сервера

```bash
ipc
```

**Пояснение:**  
`ipc` — это сокращение/алиас для команды `ip addr` или `ipconfig`, показывающей сетевые интерфейсы.

**Результат:**  
Команда показала, что сервер доступен по адресу `192.168.97.152`:
```
inet 192.168.97.152/23
```

**Зачем это нужно:**  
Чтобы понять, по какому адресу открывать приложение в браузере.

---

### Шаг 9. Создание SSH-туннеля

```bash
ssh -L 8080:127.0.0.1:8080 root@192.168.97.152
```

**Что такое SSH-туннель:**  
Это защищенный канал, который перенаправляет сетевой трафик с вашего локального компьютера на удаленный сервер.

**Разбор команды:**

| Часть команды | Что означает |
|---------------|--------------|
| `ssh` | Команда для SSH-подключения |
| `-L` | Создать локальный туннель (Local) |
| `8080` (первый) | Порт на вашем ноутбуке, который будет слушать |
| `127.0.0.1:8080` | Куда перенаправлять запросы на сервере (локальный адрес сервера) |
| `root@192.168.97.152` | К кому подключаться (пользователь и IP) |

**Как это работает (пошагово):**

1. **Вы открываете браузер** → вводите `http://localhost:8080`
2. **Ваш ноутбук** → отправляет запрос на свой локальный порт 8080
3. **SSH-клиент** → перехватывает запрос и шифрует его
4. **По SSH-соединению** → запрос уходит на сервер 192.168.97.152
5. **На сервере** → запрос расшифровывается и направляется на `127.0.0.1:8080`
6. **rcreview-api** → принимает запрос и формирует ответ
7. **Ответ** → возвращается тем же путем обратно
8. **Ваш браузер** → отображает полученную страницу

**Зачем это нужно:**  
Интерфейс работает на сервере, но мы хотим открыть его в браузере на своем ноутбуке. Прямой доступ может быть невозможен из-за сетевых ограничений.

---

### Шаг 10. Открытие в браузере

```
http://localhost:8080
```

**Что происходит:**

1. **Браузер** → обращается к локальному порту 8080 на вашем ноутбуке
2. **SSH-туннель** → перенаправляет запрос на сервер
3. **rcreview-api** → принимает запрос на сервере
4. **Сервер** → возвращает страницу логина через туннель

**Результат:**  
Вы видите страницу входа в приложение.

## Схема работы

### Общая архитектура

```
┌─────────────────────────────────────────────────────────────┐
│                       Ваш ноутбук                          │
│                                                           │
│   ┌─────────────┐    ┌─────────────────────────────┐     │
│   │   Браузер   │───▶│   http://localhost:8080     │     │
│   └─────────────┘    └─────────────────────────────┘     │
│                                          │                │
│                                          ▼                │
│                           ┌─────────────────────────┐     │
│                           │    SSH-клиент           │     │
│                           │   (локальный порт 8080) │     │
│                           └─────────────────────────┘     │
│                                          │                │
└──────────────────────────────────────────┼────────────────┘
                                           │
                                           ▼ SSH-туннель (защищенный канал)
                                           │
┌──────────────────────────────────────────┼────────────────┐
│                 Сервер (192.168.97.152)  │                │
│                                          ▼                │
│                           ┌─────────────────────────┐     │
│                           │    SSH-сервер           │     │
│                           │   (принимает туннель)   │     │
│                           └─────────────────────────┘     │
│                                          │                │
│                                          ▼                │
│                           ┌─────────────────────────┐     │
│                           │   rcreview-api          │     │
│                           │   (127.0.0.1:8080)      │     │
│                           └─────────────────────────┘     │
│                                          │                │
│                                          ▼                │
│                           ┌─────────────────────────┐     │
│                           │   Страница логина       │     │
│                           └─────────────────────────┘     │
└─────────────────────────────────────────────────────────────┘
```

### Направление запросов и ответов

**Запрос (от вас к серверу):**
```
Браузер → localhost:8080 → SSH-туннель → Сервер → rcreview-api
```

**Ответ (от сервера к вам):**
```
rcreview-api → Сервер → SSH-туннель → localhost:8080 → Браузер
```

## Возможные проблемы и решения

### Проблема: Не видно страницу логина

**Решение:**
- Проверьте, запущен ли `rcreview-api` в терминале
- Проверьте, не закрылся ли SSH-туннель
- Перезапустите API и туннель

### Проблема: Не работает SSH-туннель

**Решение:**
- Проверьте, доступен ли сервер по SSH: `ssh root@192.168.97.152`
- Проверьте, не занят ли порт 8080 на локальной машине
- Попробуйте использовать другой порт: `-L 8081:127.0.0.1:8080`

### Проблема: Address already in use

**Решение:**
```bash
# Найдите процесс, занимающий порт
sudo lsof -i :8080
# Убейте процесс или используйте другой порт
ssh -L 8081:127.0.0.1:8080 root@192.168.97.152
# Затем открывайте http://localhost:8081
```

### Проблема: Не знаю логин и пароль

**Решение:**
1. Проверьте файл `.env`: `cat .env | grep -i admin`
2. Проверьте документацию: `cat README.md | grep -i admin`
3. Проверьте код: `grep -r "password\|login" app/`

### Проблема: Браузер не открывает страницу при прямом доступе

**Решение:**
- Используйте SSH-туннель: `http://localhost:8080`
- Проверьте, что в адресной строке **http://**, а не **https://**
- Откройте в режиме инкогнито
- Очистите кеш браузера
