### Шаг 2: Создание директорий на сервере

**Где выполнять:** На машине `backup` (192.168.87.99)

```bash
#!/bin/bash
# ==========================================
# ВЫПОЛНЯЕТСЯ НА: backup (192.168.87.99)
# ==========================================

# Создаем основную корневую папку для SFTP
# mkdir -p создает папку и все промежуточные, если их нет
mkdir -p /sftp-share

# Создаем рабочую папку внутри - сюда будут ходить пользователи
# Это та самая папка, которую увидят клиенты
mkdir -p /sftp-share/sftp-share-dir

# Создаем папку для временных файлов
mkdir -p /sftp-share/temp

# ==========================================
# НАСТРОЙКА ПРАВ ДОСТУПА
# ==========================================

# Корневая папка должна принадлежать root (требование chroot)
# chown - меняет владельца
# root:root - владелец:группа
chown root:root /sftp-share

# chmod 755 - права: rwxr-xr-x
# владелец (root) - полный доступ (rwx)
# группа (root) - чтение и выполнение (r-x)
# остальные - чтение и выполнение (r-x)
chmod 755 /sftp-share

# Рабочая папка пока принадлежит root
chown root:root /sftp-share/sftp-share-dir
chmod 755 /sftp-share/sftp-share-dir
```

**Что означают права доступа (chmod):**
```
755 = rwx r-x r-x
      │   │   │
      │   │   └─── остальные: чтение + выполнение
      │   └─────── группа: чтение + выполнение
      └─────────── владелец: чтение + запись + выполнение

775 = rwx rwx r-x
      │   │   │
      │   │   └─── остальные: чтение + выполнение
      │   └─────── группа: чтение + запись + выполнение
      └─────────── владелец: чтение + запись + выполнение
```

### Шаг 3: Создание групп пользователей на сервере

**Где выполнять:** На машине `backup` (192.168.87.99)

```bash
#!/bin/bash
# ==========================================
# ВЫПОЛНЯЕТСЯ НА: backup (192.168.87.99)
# ==========================================

# groupadd - создает новую группу
# Группа для пользователей с ПОЛНЫМ доступом (чтение/запись/удаление)
groupadd sftp-full-access
# (ОПЦИОНАЛЬНО) Создать группу с конкретным GID
groupadd -g 1500 sftp-full-access

# Группа для пользователей только с ЧТЕНИЕМ
groupadd sftp-readonly
# (ОПЦИОНАЛЬНО) Создать группу с конкретным GID
groupadd -g 1501 sftp-readonly

# Проверяем, что группы создались
# grep - ищет строки с "sftp-" в файле /etc/group
grep sftp- /etc/group
# Должны увидеть:
# sftp-full-access:x:1001:
# sftp-readonly:x:1002:
```

Другие полезные опции для groupadd
```bash
# -g GID   : задать конкретный номер группы
# -r       : создать системную группу (GID < 1000)
# -f       : не выдавать ошибку, если группа уже существует
# -K KEY=VALUE : переопределить настройки по умолчанию

# Примеры:
groupadd -g 2000 sftp-full-access     # GID = 2000
groupadd -r sftp-system               # системная группа
groupadd -f sftp-full-access          # не выдаст ошибку, если существует
```

### Шаг 4: Создание пользователей с ПОЛНЫМ доступом на сервере

**Где выполнять:** На машине `backup` (192.168.87.99)

```bash
#!/bin/bash
# ==========================================
# ВЫПОЛНЯЕТСЯ НА: backup (192.168.87.99)
# ==========================================

# ==========================================
# РАЗБОР КОМАНДЫ useradd:
# ==========================================
# -m              : создать домашнюю папку
# -d ПУТЬ         : указать путь к домашней папке
# -g ГРУППА       : основная группа пользователя
# -s ОБОЛОЧКА     : командная оболочка (shell)
# -c "КОММЕНТАРИЙ": комментарий к пользователю
# ИМЯ_ПОЛЬЗОВАТЕЛЯ: логин пользователя
# ==========================================

# Пользователь для машины 192.168.87.118 (ai2)
useradd -m \
        -d /sftp-share/sftp-share-dir \
        -g sftp-full-access \
        -s /usr/sbin/nologin \
        -c "SFTP user for AI2 machine (192.168.87.118)" \
        sftp-ai2

# Пользователь для машины 192.168.87.179 (runelfrontdev)
useradd -m \
        -d /sftp-share/sftp-share-dir \
        -g sftp-full-access \
        -s /usr/sbin/nologin \
        -c "SFTP user for runelfrontdev machine (192.168.87.179)" \
        sftp-frontdev

# ==========================================
# Почему /usr/sbin/nologin?
# ==========================================
# Это специальная оболочка, которая запрещает вход по SSH.
# Пользователь сможет только подключаться по SFTP.
# При попытке ssh он увидит:
# "This account is currently not available."

# ==========================================
# УСТАНОВКА ПАРОЛЕЙ
# ==========================================

# passwd ИМЯ - устанавливает пароль для пользователя
# Будет запрошен ввод пароля (дважды для подтверждения)
echo "=== Установите пароль для sftp-ai2 ==="
passwd sftp-ai2

echo "=== Установите пароль для sftp-frontdev ==="
passwd sftp-frontdev

# Проверяем, что пользователи созданы
# id - показывает информацию о пользователе
id sftp-ai2
# Вывод: uid=1001(sftp-ai2) gid=1001(sftp-full-access) groups=1001(sftp-full-access)

id sftp-frontdev
# Вывод: uid=1002(sftp-frontdev) gid=1001(sftp-full-access) groups=1001(sftp-full-access)
```

### Шаг 6: Настройка прав доступа на сервере

**Где выполнять:** На машине `backup` (192.168.87.99)

```bash
#!/bin/bash
# ==========================================
# ВЫПОЛНЯЕТСЯ НА: backup (192.168.87.99)
# ==========================================

# ==========================================
# НАСТРОЙКА ПРАВ НА ПАПКИ
# ==========================================

# Корневая папка - ТОЛЬКО root (требование chroot)
# Это БЕЗОПАСНОСТЬ: пользователи не могут выйти за пределы своей папки
chown root:root /sftp-share
chmod 755 /sftp-share

# РАБОЧАЯ папка - полный доступ для группы sftp-full-access
# root: владелец root
# sftp-full-access: группа, у которой есть права на запись
chown root:sftp-full-access /sftp-share/sftp-share-dir

# 775 означает:
# rwx (владелец root) - полный доступ
# rwx (группа sftp-full-access) - полный доступ
# r-x (остальные) - только чтение
chmod 775 /sftp-share/sftp-share-dir

# Создаем папку для загрузок с полными правами
mkdir -p /sftp-share/sftp-share-dir/uploads

# Папка uploads принадлежит пользователю sftp-ai2 и группе sftp-full-access
chown sftp-ai2:sftp-full-access /sftp-share/sftp-share-dir/uploads
chmod 775 /sftp-share/sftp-share-dir/uploads

# Создаем папку для логов
mkdir -p /var/log/sftp
chmod 755 /var/log/sftp
```

### Шаг 7: Настройка SSH сервера (главный шаг!)

**Где выполнять:** На машине `backup` (192.168.87.99)

```bash
#!/bin/bash
# ==========================================
# ВЫПОЛНЯЕТСЯ НА: backup (192.168.87.99)
# ==========================================

# Делаем резервную копию конфигурации SSH
# cp - копирует файл
# .backup - расширение для резервной копии
cp /etc/ssh/sshd_config /etc/ssh/sshd_config.backup

# Добавляем настройки в конец файла
# cat >> файл << 'EOF' - добавляет текст в конец файла
# EOF - маркер конца текста
cat >> /etc/ssh/sshd_config << 'EOF'

# ==========================================
# НАСТРОЙКИ SFTP CHROOT
# ==========================================

# Подсистема SFTP (должна быть включена)
Subsystem sftp internal-sftp

# ------------------------------------------------------------------
# ПРАВИЛА ДЛЯ ПОЛЬЗОВАТЕЛЕЙ С ПОЛНЫМ ДОСТУПОМ
# ------------------------------------------------------------------
Match Group sftp-full-access
    # ChrootDirectory - "корневая" папка для пользователя
    # Пользователь не сможет выйти за ее пределы
    ChrootDirectory /sftp-share
    
    # ForceCommand - принудительно запускает только SFTP
    # internal-sftp - встроенный SFTP сервер
    ForceCommand internal-sftp
    
    # Запрещаем интерактивный доступ
    PermitTTY no
    
    # Отключаем все лишние функции для безопасности
    PermitTunnel no
    AllowAgentForwarding no
    AllowTcpForwarding no
    X11Forwarding no
    
    # Разрешаем вход по паролю
    PasswordAuthentication yes
    
    # Таймаут сессии (если нет активности)
    ClientAliveInterval 60      # проверка каждые 60 секунд
    ClientAliveCountMax 3       # максимум 3 неудачных проверки

# ------------------------------------------------------------------
# ПРАВИЛА ДЛЯ ПОЛЬЗОВАТЕЛЕЙ ТОЛЬКО С ЧТЕНИЕМ
# ------------------------------------------------------------------
Match Group sftp-readonly
    ChrootDirectory /sftp-share
    
    # -R означает "только чтение" (Read-only)
    # Пользователь не сможет создавать/удалять/изменять файлы
    ForceCommand internal-sftp -R
    
    PermitTTY no
    PermitTunnel no
    AllowAgentForwarding no
    AllowTcpForwarding no
    X11Forwarding no
    PasswordAuthentication yes
    ClientAliveInterval 60
    ClientAliveCountMax 3

EOF

# ==========================================
# ПРОВЕРКА И ПЕРЕЗАПУСК
# ==========================================

# sshd -t - проверяет конфигурацию на ошибки
sshd -t

# Если ошибок нет (команда ничего не вывела) - перезапускаем
systemctl restart sshd

# Проверяем статус
systemctl status sshd
```

### Шаг 8: Настройка SSH ключей на клиентских машинах

```bash
#!/bin/bash
# ==========================================
# ВЫПОЛНЯЕТСЯ НА: 192.168.87.118 (ai2)
# И НА: 192.168.87.179 (runelfrontdev)
# ==========================================

# Генерируем SSH ключ для SFTP
# ssh-keygen - утилита для создания ключей
# -t rsa - тип ключа (RSA)
# -b 4096 - длина ключа в битах (4096 - очень надежно)
# -f ~/.ssh/id_rsa_sftp - файл для сохранения ключа
# -N "" - без парольной фразы (пустой пароль)
ssh-keygen -t rsa -b 4096 -f ~/.ssh/id_rsa_sftp -N ""

# После выполнения создадутся два файла:
# ~/.ssh/id_rsa_sftp - ПРИВАТНЫЙ ключ (НИКОМУ НЕ ПОКАЗЫВАТЬ!)
# ~/.ssh/id_rsa_sftp.pub - ПУБЛИЧНЫЙ ключ (можно показывать)

# ==========================================
# КОПИРУЕМ ПУБЛИЧНЫЙ КЛЮЧ НА СЕРВЕР
# ==========================================

# Способ 1: Через ssh-copy-id (самый простой)
# Будет запрошен пароль пользователя sftp-ai2
ssh-copy-id -i ~/.ssh/id_rsa_sftp.pub sftp-ai2@192.168.87.99

# Способ 2: Вручную (если ssh-copy-id не работает)
# Показываем публичный ключ
cat ~/.ssh/id_rsa_sftp.pub

# Копируем вывод и выполняем на сервере (см. следующий шаг)
```

### Шаг 9: Добавление ключей на сервер (если вручную)

**Где выполнять:** На машине `backup` (192.168.87.99)

```bash
#!/bin/bash
# ==========================================
# ВЫПОЛНЯЕТСЯ НА: backup (192.168.87.99)
```

### Вариант 1: Double Commander (Рекомендую!)

**Double Commander** - отличный двухпанельный файловый менеджер, похожий на Total Commander.

```bash
# ==========================================
# УСТАНОВКА НА КЛИЕНТСКОЙ МАШИНЕ
# ==========================================

# Установка на Ubuntu/Debian
sudo apt-get update
sudo apt-get install -y doublecmd-qt

# Или через snap
sudo snap install double-commander

# Запуск
doublecmd
```

**Как подключиться к SFTP в Double Commander:**

1. Запустите Double Commander
2. Нажмите `Ctrl+N` или меню "Команды" → "Сетевое окружение"
3. Нажмите "Добавить" → "SFTP"
4. Заполните поля:

```
Имя подключения: Backup сервер
Хост: 192.168.87.99
Порт: 22
Имя пользователя: sftp-ai2 (или sftp-frontdev)
Пароль: [ваш пароль]
Путь: /sftp-share-dir
```

5. Нажмите "OK"
6. Дважды кликните на созданное подключение

**Скриншот-описание:**
```
+------------------------------------------+
| [🔗 Backup сервер]  [📁 Локальная]       |
+------------------------------------------+
|  📁 sftp-share-dir  |  📁 home           |
|  📄 file1.txt       |  📁 downloads      |
|  📄 file2.pdf       |  📁 documents      |
|  📁 uploads         |  📄 test.txt       |
+------------------------------------------+
|  [F5 Копировать] [F6 Переместить]        |
|  [F7 Создать] [F8 Удалить]               |
+------------------------------------------+
```

**Горячие клавиши в Double Commander:**
- `F5` - копировать файлы
- `F6` - переместить файлы
- `F7` - создать папку
- `F8` - удалить
- `Ctrl+C` / `Ctrl+V` - копировать/вставить

## КОМАНДЫ ДЛЯ ПРОВЕРКИ НА СЕРВЕРЕ

```bash
#!/bin/bash
# ==========================================
# ВЫПОЛНЯЕТСЯ НА: backup (192.168.87.99)
# ==========================================

# Проверка прав на папки
ls -la /sftp-share/
# Должны увидеть:
# drwxr-xr-x 3 root root 4096 ... .
# drwxrwxr-x 3 root sftp-full-access 4096 ... sftp-share-dir

cat /etc/passwd | grep sftp
# Должны увидеть:
# sftp-ai2:x:1001:1001:SFTP user for AI2...
# sftp-frontdev:x:1002:1001:SFTP user for runelfrontdev...
# sftp-reader:x:1003:1002:SFTP readonly user...

cat /etc/group | grep sftp
# Должны увидеть:
# sftp-full-access:x:1001:
# sftp-readonly:x:1002:

# Проверка активных подключений
ss -tnp | grep :22
# или
netstat -tulpn | grep :22

tail -f /var/log/auth.log | grep sftp
```
